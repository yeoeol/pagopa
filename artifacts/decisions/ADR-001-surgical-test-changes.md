# ADR-001: 대상 테스트 내부의 외과적 변경으로 시작

- 날짜: 2026-09-03
- 상태: 채택

## 맥락

기존 동시성 테스트는 준비와 실행 코드가 반복되고 길지만, 공용 도구로 즉시 추출하면 여러 테스트와
Fixture에 영향이 퍼진다. 사용자는 먼저 낮은 회귀 위험으로 하네스를 적용하고 이후 확장 가능성을
원한다.

## 결정

v0.1은 A 방식을 사용한다. 승인된 대상 테스트 파일과 그 내부 private helper만 수정하며 운영 코드,
빌드 설정, 공용 Fixture와 공용 테스트 유틸리티를 변경하지 않는다.

## 버린 대안과 이유

- B 방식 — 공용 concurrency runner와 Fixture를 즉시 추출: 재사용성은 높지만 초기 변경 범위와
  검증 비용이 커지고 현재 테스트의 서로 다른 요구를 너무 일찍 추상화할 위험이 있다.
- 리팩터링 없이 테스트만 계속 추가: 가장 빠르지만 기존 실패 원인인 중복·가독성 저하를 반복한다.

## 가정·트레이드오프

- 작은 중복보다 낮은 회귀 위험과 명확한 승인 범위를 우선한다.
- 파일 내부 helper가 늘어날 수 있으며 여러 파일 사이의 중복은 당분간 허용한다.
- 테스트 코드와 검증 산출물 형식은 B 방식에서도 유지해 마이그레이션 비용을 줄인다.

## B 방식으로 전환하는 방법

1. 반복되는 setup·동시 실행·outcome 집계를 두 개 이상의 테스트 파일에서 확인한다.
2. 공용화할 API와 호출 예시를 테스트 목록으로 작성한다.
3. 영향받는 모든 테스트 파일과 회귀 범위를 사용자에게 보여주고 별도 승인받는다.
4. 공용 도구를 추가한 뒤 기존 테스트를 한 파일씩 이전하고 매 단계 회귀 테스트를 실행한다.
5. with/without 비교로 가독성, 실행 안정성, 유지보수성이 실제로 좋아졌는지 확인한다.

## 재검토 조건

- 같은 동시성 실행 코드가 두 개 이상의 테스트 클래스에서 반복된다.
- 한 대상 테스트의 local helper가 핵심 시나리오를 가릴 정도로 커진다.
- 동시성 outcome 집계나 자원 정리 결함이 반복된다.
- 공용 Fixture 변경 요구가 세 번 이상 발생한다.

재검토 조건이 생겨도 자동 전환하지 않고 새 청사진과 사용자 승인을 요구한다.
